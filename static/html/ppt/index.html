单线程的概念

单线程程序在任一时刻只能执行一个任务。整个程序从启动到结束始终只有一个执行流，这种模式简单、易于理解，但当程序中有多个耗时任务时，会造成程序响应变慢、界面卡顿等问题。单线程适用于任务较少或计算量较低的场景，优点是无需考虑线程同步等问题，缺点是无法充分利用多核CPU资源，性能扩展性较差。

多线程的概念

多线程是指在一个进程内同时存在多个执行流，每个线程可以独立执行任务，从而实现并发操作。多线程编程能够提高程序的响应速度和利用率，尤其在I/O密集型、网络编程、GUI程序等场景下表现明显。但与此同时，多线程也带来了线程间资源共享、同步与竞争等问题，需要开发者谨慎设计，避免死锁、数据不一致等问题。

线程同步与通信

多线程编程虽然能提高程序效率，但线程之间的并发访问往往会引发共享资源的竞争问题。为确保数据一致性，需要使用线程同步技术，如synchronized关键字、锁机制、信号量等。同步的核心思想是保证同一时刻只有一个线程访问共享资源，从而避免数据混乱。

同时，多线程程序中常常需要线程之间的通信，如通过wait()、notify()和notifyAll()等方法实现线程间协调工作。合理运用这些机制可以使多线程程序既高效又安全。

常见多线程问题

竞争条件:

多个线程并发修改共享数据，导致数据状态不确定。

死锁:

两个或多个线程因争夺资源而相互等待，导致程序无法继续执行。

饥饿与活锁:

部分线程长时间无法获得CPU资源或不断重复执行无效操作。

内存可见性问题:

多个线程之间对共享变量的更改可能不可见，需要使用内存屏障或同步机制解决。

闰年判断代码回顾

闰:

闰”字本身有“余数”“额外”的意思，闰年就是额外增加了一天的年份，以调整历法与地球实际公转周期的偏差

出处:

《尚书∙尧典》中记载，以“期三百有六旬有六日，以闰月定四时，成岁”这是我国最早关于古代原始阴阳历的记载。

公历置闰:

公元年数能被4整除的年为闰年，其余年为平年。但对整世纪年（如1600，1700……）只有世纪数也能被400整除的才是闰年，其余的虽然年数都能被4整除，但仍为平年，比如2000年是闰年，而1900年不是。

判断闰年 


    // 判断当前年为闰年的方法
    private boolean isLeapYear(int year) {
        return (year % 4 == 0 && year % 100 != 0) || (year % 400 == 0);
    }

判断质数 


    // 判断当前数是否是质数的方法
    public boolean isPrime(int num) {
        if (num <= 1) return false;
        if (num == 2) return true;
        if (num % 2 == 0) return false;
        
        for (int i = 3; i <= Math.sqrt(num); i += 2) {
            if (num % i == 0) {
                return false;
            }
        }
        return true;
    }
